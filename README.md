# 我的词库 · 背单词

一个离线可用的英语词汇学习网站。词条与分单元方式取自 `SAT词汇2300打印版.pdf`：**原书每一页 = 一个单元**，共 36 个单元、2389 个词条；末尾另加 **Unit 37「错词本」**，是从 `延奥-错词整理（7.3-8.30）.xls` 整理出来的 149 个错词（其中 69 个与原书重复，音标和例句共用）。SAT 部分合计 2538 条、2441 个不同的词。

另外整本收了新东方《绿宝书》托福词汇（第十二次优化 2）：`新东方托福【绿宝书】-托福词汇.xlsx`，原表一张 Sheet 一个 List、共 48 个 List，导进来也是一 List 一个单元（u 1001–1048），和 SAT 的 37 个单元分得清清楚楚，互不干扰。原表 **4249** 行，i 从 5001 开始编号，跟 SAT 那 2538 条完全不挨着。其中 4 行（List 32 acid、List 40 conceivable、List 41 drain、List 43 delirium）原表「意思」那一格是空的格式残留或错填了英文例句，音标是原表真实数据、照单全收，释义是事后按词义补的，不是原书内容。

托福这 4249 个词现在张张都带内置例句（第十七次优化）：跟 SAT 词表重复的 804 个词直接复用 SAT 那句（`RICH` 按单词字符串取值，天然共享，见 `data/rich.js`），剩下 3445 个没有的由 `data/toefl_rich.js` 补上——写法和例句风格照抄 `aiPrompt()`/`AI_SCHEMA`（见下面「AI 例句」），只是离线一次性造好存进数据文件，不占用你自己的 API Key。

又加了一份雅思核心词汇（第十八次优化）：`雅思核心词汇.xlsx`，原表只有一张按话题分类排列的总表、共 639 词，不像托福那样一 Sheet 一个 List，所以按原表顺序切单元。第十八次优化时是每 70 词一个、共 10 个单元；**第十九次优化改成每 90 词一个单元，共 8 个（u 2001–2008，639 = 7×90 + 9，最后一个只有 9 词）**。i 从 10001 开始编号，跟托福那 4249 条（i 5001–9249）分开；i 只跟原表顺序有关、跟每个单元多少词无关，所以改单元大小不会让已有的认识 / 不认识 / 星标 / 颜色记录挪位置——它们都是按 i 存的。

雅思这 639 个词条现在张张都带例句（第十九次优化）：用原表自带的「例句」列（每词一句，偏短的雅思风格，平均 7 个词），中文翻译由 `src/ielts_zh/L01–L08.tsv` 补上（一个 List 一个文件，每行 `编号§单词§例句§译文`，译文里恰好一处 `**…**` 标出对应词义，格式同 SAT / 托福）。存进 `data/ielts_rich.js`（`window.IELTS_RICH`），**按词条编号 i 取、不按单词取**：雅思词有一半在 SAT / 托福里也有，借那边的例句会词义对不上（比如 `academic` 在 SAT 里那句用的是「空谈」义、`conflict` 那句用的是动词），所以雅思词优先用自己的，SAT / 托福那边的例句一个字没动。查找在 `app.js` 的 `rich()`：先查 `IELTS_RICH[w.i]`（条目里的 `w` 要跟词条对得上才用——第二十次优化以前自己导入的词编号是从 10000 往上排的，会撞上雅思的 10001–10639，不能撞了号就拿到雅思的例句；撞号本身第二十次优化从源头解决了，见下，这道核对留着当保险），查不到再回头用共享的 `RICH`；原来借 SAT 例句时显示的词根（59 个词有）会并过来，不丢。

有 9 句例句改写过、1 个词条改了拼写：应用要在例句里找到这个词（卡片高亮靠 `wordPat`、例句填空题靠 `blankAt`），原句里是 `rose` / `grew` / `fell` / `levelled off` / `remained stable` 这种过去式，或词藏在更长的单词里（`Overconsumption` 里的 consumption、`Arachnophobia` 里的 phobia），或写成 `Inner-city` / `the right`（词条是 `rights`），高亮和填空都认不出，所以改写成带原词形的说法；另外原表里 `cultural shock` 是笔误（例句里写的是 culture shock），改成了 `culture shock`。这些都登记在 `src/build_ielts.py` 的 `EDITED` / `WORD_FIXES` 里，TSV 里的例句跟原表对不上又没登记的话，构建会报错、一个文件都不写。`test/ielts.test.js` 用应用自己的 `wordPat` / `blankAt` 把 639 条逐个验一遍。

自己导入／手动加的词和雅思词撞号，修掉了（第二十次优化）：自建词的编号原来是从 10000 往上排的（`doImport` 里的 `nextI`、手动添加里的 `base`），而 2026-09-26（第十八次优化）加进来的雅思词占了 i 10001–10639，所以那天之前存下来的自建词，编号有可能和某个雅思词一模一样。认识 / 不认识 / 曾错过 / 星标 / 选中 / 颜色都是按 i 存的（`store.prog / hist / star / sel / col`），撞号的两个词就共用了同一份记录：学过自建词，同号的雅思词也跟着显示「已掌握」，反过来也一样；删掉自建词时还会把雅思词的记录一起删掉。**新的自建词现在从 100000 往上排**（`pure.js` 的 `CUSTOM_ID_FLOOR` 和 `nextCustomId()`，导入和手动添加都从这一处取号，要改规则只改这里）；内置词表占的 SAT 1–2538、托福 5001–9249、雅思 10001–10639 都远在它下面，以后再加内置词表，编号也别用到 100000 以上——`test/customid.test.js` 用真实的词表数据卡着这一条。词卡和浏览列表里编号变成 6 位（`NO. 100000`），版面放得下，手机宽度也看过。

**已经存下来的撞号自建词，打开时一次性换号**（`store.iv`，跟 `store.pv` / `store.hv` 是同一个套路，只跑一次；逻辑是 `pure.js` 里的纯函数 `renumberCollidingCustom`，不改传进去的东西，对结果再跑一遍什么都不变）：自建词的编号只要跟内置词表里的某个编号相同，就换成 100000 以上的新号；没撞的（包括编号正好是 10000 的那个，内置词表里没有 10000）一个不动。**那份共用的记录整份跟着自建词走，同号的雅思词回到「未学」。** 这是没法两全时挑的：9-26 起两个词一直往同一个键里写，那份记录已经拆不开了，只能挑一边留。留给自建词，是因为这个编号是它先占着的、雅思词 9-26 才到；而最常见的情形——学过自己导入的词、还没碰过同号的雅思词——这样刚好原样恢复，还顺手清掉了雅思词身上莫名其妙的「已掌握」。反过来留给雅思词，自建词的进度会被抹掉，雅思词却照旧带着假进度；两边各留一份副本最糟，假进度谁也抹不掉。**可能丢的是**：如果 9-26 之后你在雅思卡片上也点过那几个同号的词（比如 List 01 开头的 `academic`、`achieve`……），那些认识 / 星标 / 颜色 / 选中会跟着记录一起去了自建词那边，雅思词要重新点。受影响的只是编号落在 10001–10639 的自建词，和与它们同号的那些雅思词；没有这种自建词的话，什么都不会变。迁移出错不会挡着应用打开（保持原样，下次再试）。

加了一套「乱序版」单元（第二十一次优化，10 个单元）：照 `2300 高密度便携版.pdf` 分——那份 PDF 是一张大表，24 个 List、每个 List 10 行 × 10 列，词从左到右、一行接一行按字母排。**竖着的每一列是一个单元**：一列从第 1 页贯穿到第 9 页，a 到 z 都有，233 词（第 10 列 232）。单元里的顺序用固定种子打乱一次后写死，每次打开都一样；想每次换个顺序，用排序里的「随机」。**首页标题下面有「原版 / 乱序版」开关**，乱序单元只在乱序版里出现，原版照旧是原书、错词本、托福、雅思和自己导入的（开关记在 `store.set.shuf`，下次打开还是上次那一套）；切到乱序版时，顶上的已掌握 / 待复习 / 总词条、整理错词、测验错词也只算乱序单元里的词（`app.js` 的 `homePool`），导入词表 / 手动添加 / 合并单元收起来，它们都落在原版那一套里。标题「乱序 01」起，u 从 3001 起，数据在 `data/shuffle.js`，由 `src/build_shuffle.py` 从 `../2300 高密度便携版.pdf` 生成。**乱序单元不自带词条**：`ids` 按顺序指向原书词条（`app.js` 的 `unitWords`），认识 / 不认识 / 星标 / 颜色都按 i 存，所以跟原书 36 个单元共用一份进度——在乱序单元里标了不认识，原书那一页里同一个词也是不认识；首页的总词条、已掌握不会重复算。PDF 里有十来处拼写错误（amlgamate、tumoil、sef-critical……），在 `build_shuffle.py` 的 `FIXES` 里对到 App 词条的拼法；还有对不上的格子，构建会报错、不写文件。跟 PDF 对不齐的另外三类，是 2026-10-23 跟你商量定的：PDF 的 charismatic、colloquial、combative 这三个词形 App 里没有，用同词根的 charisma、colloquially、combat 那三条（也登记在 `FIXES`）；PDF 把 continual、discretion、intrusive 印了两遍，在相邻两列，所以这三个词各在两个单元里，跟纸上一样；原书 36 个单元里有 35 个词 PDF 没收（abhor、anecdote、benefit、career……），乱序版不加，它们照旧在原版里。10 个单元合计 2329 格、2326 个不同词条。

第二十二次优化（2026-10-30）三处小改：**取消了「模糊」**，评级只剩「不认识」（键 1）和「认识」（键 3，2 键空着；第二十二次刚改时是键 2，第二十三次改回 3）；老存档里标着模糊的词，打开时一次性并进「不认识」（`store.pv` 升到 3），不补记「曾错过」；测验答错现在也记成「不认识」。**学习卡翻开之前的「例句提示」里，自己生成／自己加的例句也一起显示**（只给英文，键 D 朗读第一句），原来只给书上那一句、没有书上例句的词就什么提示都没有。用自己的 Anthropic Key 生成例句时，请求里的 `output_config.effort` 从 `low` 调到了 `medium`。

第二十三次优化（2026-10-30）：**大单元学习时答题卡不再跟着晃**——原来每换一个词都把当前那个点滚到点阵正中，词一多每换一行点阵就挪一下；现在记住上次滚到哪（`app.js` 的 `railKeep` / `railPlace`），当前的点还在视野里就不动，出了视野才往下翻一屏、让它落在第二行；从搜索跳过来找词时照旧放正中。**词卡和浏览列表标出「单元里第几个」**：词卡编号后面多了「第 k / N 个」，浏览页每行左边的数字改成单元里的序号（原来的编号挪进鼠标悬停提示）；序号按单元自己的顺序算（原书顺序，乱序单元就是那份写死的乱序），不随排序和颜色筛选变（`unitSeq`）。「认识」的快捷键改回 **3**，2 键空着不做事。**单词发音默认换成有道真人录音**（`https://dict.youdao.com/dictvoice`，国内直连）：只管单词和短语，整句它不给，例句照旧用系统声音；没网、查不到这个词、2.5 秒还没响、或者在 claude.ai 上被拦，都自动退回系统声音。设置里「单词发音」可以改回一直用系统声音（`store.set.wsrc`）。另外改了「曾错过」的记账：第一次就标「不认识」不再算错过，只有认识之后又掉回不认识才算；旧的「曾错过」记录分不清是哪种，打开时一次性清空。

第二十四次优化（2026-10-30）：**进新词后自动发音不再干等一秒多**——有道的录音要等 1 秒多才回来，响应里也没有缓存头，原来每读一个词都现取一次。现在一进卡片就在后台先取好这个词和下一个词的录音（学习、整理错词、拼写检测都是），真要读的时候直接播，实测从 1.2 秒左右降到几十毫秒；最近 12 个词的录音留在内存里，回头再听不用重取（`app.js` 的 `ydGet` / `ydPrefetch`）。页面头上加了到 `dict.youdao.com` 的预连接，第一个词也快一点。**设置里「自动朗读单词」可以选什么时候读**（学习和整理错词）：「显示释义时读（空格）」是默认，按空格或点「显示释义」就读；「一换到新词就读」是换到下一个词马上读，翻开时不重复读；也可以「不自动读」（`store.set.autoAt`：`reveal` / `enter`，关掉还是 `store.set.auto = false`）。拼写检测照旧答完才读。

第二十五次优化（2026-10-30）：**大单元的答题卡滚下去点词不再弹回去**——点阵重画时先按估计的行高（14px）撑内容，`scrollTop` 这时候设进去会被截短；`ResizeObserver` 刚挂上还会先报一次，又把行高打回估计值重算一遍。233 词的单元滚到底（575）点一个词，弹回 417，刚点的点还掉到视野外。现在等真实行高的占位块撑好才设 `scrollTop`，`ResizeObserver` 只在列数或行高真变了才重放；占位块减掉行距，内容总高度不再随滚动变；在点阵上亲手点的词一格都不挪（`railHold`），半露在边上的点也不翻页。**大单元（超过 120 词）的答题卡加宽成 8 列**，点的大小不变，233 词从 59 行缩到 30 行，窗口高 800 左右就一屏放下，不用滚（`.rail-wide`；小单元和窄屏不变）。**「认识」不再分两种颜色**：不认识改成认识就是纯红，去掉了圆点的琥珀描边、词卡左边的半红半琥珀、图例里的「认识（曾错过）」；「曾错过」这个记录还在，词卡上的小标、「先曾错过」排序、首页入口都照旧。**浏览页每行加了「不会」按钮**：点一下把这个词归到不认识，再点一下撤回到标之前（`toggleMiss`，认识的词标错了连那次「错过」一起退掉；撤回只在这次打开页面期间有效，刷新后再点就是清成未学）；只改这一行、答题卡上的点和头上的「整理错词」数，不整页重画，列表和答题卡都停在原处。选择模式和编辑模式下不显示。

第二十六次优化（2026-10-30）：**在答题卡上点词，整页也不再跳回顶部**——答题卡加宽之后 233 词不用内部滚动了，但矮一点的窗口要把整页往下滚才看得到最后几行，这时点一个词，`go()` 换页时把页面拉回顶上，刚点的点就掉到屏幕底边（实测页面从 200 回到 0，点从 623 掉到 823，窗口才 830 高）。现在 `goN(k, true)` 记下点之前的位置再放回去，点还留在鼠标底下；上一个、下一个、评级照旧回到顶上，看新词。**学习页的词卡放大**（宽度超过 900 才生效）：学习页最宽从 1180 放到 1480（`html.studying`），头部收紧让词卡和答题卡上移约 70px，1520×830 的窗口里卡片从 832 宽到 1132；单词 64→76px、音标 18→22px、例句 18→22px、释义 17→21px，按钮也跟着大一点。释义和例句翻译的大小仍然跟着设置里的「中文字号」走。字号写在 `.wcard` 上，整理错词用的是同一张卡，一起变大。

第二十七次优化（2026-10-30）：**整理错词换成学习页的版面**——原来卡片窄（最宽 780），上面压着一排点子，1520 宽的窗口右边空出一大块。现在词卡在左、答题卡在右，宽度、字号、收紧的头部都跟学习页一样（`html.studying` 也管这一页），标题和卡片之间的点子去掉了；卡片下面加了「上一个 / 下一个」。答题卡上是这一轮的状态，不是学习进度：朱红已清、琥珀又错了、空的待过（`railHtml` 的 `tone` 参数，`reviewTone`）。超过 120 词也有答题卡了（原来点子直接不画），走跟大单元一样的 8 列虚拟滚动。**已清掉的红点也能点开看**：点一下翻开释义直接看（`route.peek`），队列不动；标「认识」或按 ← → 回到刚才那个词，标「不认识」就放回队尾、「已清」减一（`rateReview`）。全部过完的页面旁边也留着答题卡，一样能点开。<kbd>↑</kbd> <kbd>↓</kbd> 现在跟学习页一样在答题卡上换一行（原来跟 ← → 重复），落到红点就翻开看；评级和上一个、下一个之后回到页面顶上，点答题卡时页面不动。百分比从进度条下面挪到了三个数旁边。

第二十八次优化（2026-10-31）：**单词发音换成词典的真人录音**。起因是 `amateurish` 读得不对：有道很多词没有真人录音，返回的是机器合成（这个词的美音就是 24kHz、32kbps 的合成音），文件格式又五花八门，分不清真假。现在 6185 个词里 **6107 个（98.7%）用词典录音**：牛津学习词典 6011 个、剑桥 87 个、朗文 2 个、Wikimedia Commons 7 个，每一条录音都真的下载核对过（12576 个，全部能打开、时长正常），并量过响度按 -21 LUFS 压平。词典没收的短语里有 14 个拆开逐词放牛津录音；剩下 64 个（60 个单词、4 个短语）三家词典都没有，用有道，词卡上标「未核对读音」。

第二十九次优化（2026-10-31）：**选择模式按 Esc 直接退出**，已勾的词留着，有弹窗时先关弹窗。**单元可以改名**：单元标题旁边点「改名」，内置单元留空保存就换回原名，标题后面一直写着原来的名字（比如原书第几页），对照纸质书不会乱；名字和学习进度一样存在这台电脑的浏览器里。测验、拼写做到一半改名不会打断这一题。另外 `src/update_pron.py` 会跳过不像单词的行：上一次剪贴板里其实是命令本身，被当成一个新词写进了 `src/oxscan.jsonl`，这一行已经删掉。

第三十次优化（2026-10-31）：**新词不用跑脚本也能找到牛津录音**。原来网页只会试 `词__us_1` 这一种地址，有三类词找不到：`con`、`aux`、`nul` 开头的词（这几个开头是 Windows 保留名，牛津的文件名前面多一个 x，如 `xconcept`）、带连字符的词（文件名是 `one_way_1_us_1`）、这个口音要到 `_2` 或 `_1_rr` 才有录音的词。`pure.js` 的 `pronGuesses` 把这些规律都排进去，英美各自按顺序试，第一个能播的就用。抽查发音表里 759 个词，假装是新词，744 个（98%）能在牛津找到；没找到的主要是拼写变体（`catalog`、`civilisation`），再试朗文，最后才用有道。之前查过的新词打开后会按新规则重查一遍。`src/update_pron.py` 变成可选：只有想把多音词分开两个喇叭时才需要跑。

第三十一次优化（2026-10-31）：**单元可以分组**：首页默认分成 SAT 词汇、托福绿宝书、雅思核心词汇三组，点进去是组里的单元，也能新建、改名、挪单元、撤销分组。**生词本变成一个单元**：有自己的浏览、学习、测验、拼写和答题卡，从生词本点进一个词，答题卡只显示生词本里的词。**测验答对不再自动标成认识**：结算页列出答对的词，自己决定标哪些，蒙对的可以去掉；答错照旧归到不认识。**设置改成分类**：左边六个分类，右边一行一项，手机上分类横着摆；「清空学习进度」挪进「词表与数据」，不再挨着「完成」。**答题卡四周加了边框**，看得出这一块是自己滚动的。

音标也换成词典的（`data/pron.js`，格式见 `pure.js` 的 `pronList`）：音标和录音出自同一条目，切英美音时音标跟着变。换完有 390 个词的主重音位置跟旧音标不一样，`amateurish` 的 `/æməˈtɜːrɪʃ/` 就是其中之一，这也是「听着不对」的另一半原因。读音随词性变的词（96 个，`abstract`、`desert`）词卡上按词性各一个喇叭，P 键和自动朗读读词表里第一个词性；词表没收的词性不放（`lead` 词表只有动词，就不放「铅」的读音）。

录音不进仓库，`data/pron.js` 只存地址，浏览器直接从词典网站取（Wikimedia 的 7 个词共 8 个文件是开放授权的，放在 `data/audio/`，来源见那里的 `CREDITS.txt`）。国内不开 VPN 能打开：站长工具 16 个以上节点从牛津官网拿到 200，用时 1–2 秒，录音地址也在手机流量下听过。第一次取要 1–3 秒，所以进词时先取好当前词和下一个词，牛津的等待时间放宽到 6 秒，宁可慢一点也不退回可能读错的有道；连续失败三次歇五分钟，改用有道，设置里写明。单文件版带着同一张表，音质一样。

**新词和短语**：网页第一次显示新词时自己去试牛津的英美录音地址（有规律，抽查 759 个词 98% 能中，见第三十次优化），没有再试朗文，查到的存进 `store.pronx`（`app.js` 的 `probeNew`），所以任何一台电脑加词都一样。短语优先用词典整句录音，没有就拆成单词连着放（`pure.js` 的 `phraseClips`）；含多音词或 a / an / the 的不拆，交给有道整句读。这样进不了多音词分喇叭和统一音量，想补齐就走全流程：设置 → 词表 →「复制还没进发音表的词」，然后

    pbpaste | python3 src/update_pron.py - --push

查词典（`src/scan_pron.py`）、取录音量音量（`src/measure_pron.py`）、生成发音表（`src/build_pron.py`）、跑测试、生成单文件版、提交推送，测试不过就停下。不带参数跑是补内置词表里新加的词。查词典时只收词头完全一样或只是英美拼写不同的条目：牛津常把 `aluminum` 跳到 `aluminium`、`bookstore` 跳到 `bookshop`，读音不一样，这类交给下一家。

同一轮的其他改动：**设置 → 外观可以换背景色调**，11 个预设，或者拖色相、浓淡选任意颜色，深色模式跟着变（`app.css` 的 `[data-tone]` 用 OKLCH 推出全套中性色，朱红不动）。**首页进度不再是 233 个空心胶囊**，设置里三选一：色块（每 10 词一格）、进度条、条带；答题卡也去掉了空心描边。**整理错词的点子放回卡片上面**，一眼跟学习页分得开，←→ 沿着点子走，已清掉的词也能到，全部过完的页面也能走。排序删掉「先曾错过」「先未学」，AI 例句只留 DeepSeek，存过的 Anthropic Key 打开时清掉。开发服务器改成多线程，原来同时加载十几个脚本时偶尔断连。

**有道录音的音量拉平**（第二十四次优化）：有道的录音响度不一，美音有一成（约 600 条）挤在 -22 到 -26 LUFS，多数词在 -16 左右。它不带跨域头，网页拿不到采样，Web Audio 也接不了，所以在本地把 6185 个词的英美两种录音都量了一遍（`src/measure_yd.py`，结果存在 `src/ydlufs.tsv`），生成音量表 `data/ydgain.js`，播放时按表把偏响的压到 -21 LUFS（`app.js` 的 `ydGainOf`）。`volume` 最多到 1，所以只能压不能放大：整体比原来小约 5 dB，美音的离散度从 2.45 dB 降到 0.71 dB，还有约 2% 的词比目标轻 3 dB 以上。表里没有的词（自己加的）按中位数压。想换目标响度，改 `TARGET` 后 `python3 src/measure_yd.py --build src/ydlufs.tsv` 就行，不用重新量。

| 词根（2441 词中的 1525 个） | 只给拆得开、拆了确实有用的词。写法是「前缀（义）+ 词根（义，同 xxx）→ 引申」 |

| 颜色分组 | 音标旁边那颗小圆点，六色随便标，用来把一个单元切成几小批 |

词根为什么只剩 62.5%：第四次优化删掉了所有**只讲古语出处**的注释。像「拉丁 adulari（摇尾巴）」「古英语 ceorl（乡下汉）」这种，
说的是词源学，不是记忆法 —— 那个古语形态在英文拼写里根本看不见，背了也用不上。删掉了 146 条这样的整条注释；
另有 194 条是「abs-（离开）+ tem（酒，**拉丁 temetum**）」这样把出处塞在括号里的，只抹掉出处、拆分留着。
现在剩下的每一条，拆出来的部件都是你在这个词的拼写里**看得见**的。

例句为什么只留一个：两个短句不如一个长句。现在每句 14–26 词（平均 17.2），生词放在主句里、句子的其余部分依赖它或解释它 —— 上下文足够多，看一遍就能记住它到底在什么场合用。

设置里可以打开「**例句的中文翻译先蒙起来**」：译文打上毛玻璃，先自己读英文，点一下再对答案。

## 发音

默认**美音**。系统里 en-US 的语音有二十来个是 macOS 的玩笑音色（Albert、Bubbles、Zarvox…），按名称排序时排在 Samantha 前面，「取第一个匹配的语音」就会挑到它们。现在会按音质排序挑选，**带 Natural / Neural / Enhanced / Premium / Online 字样的神经网络音色优先**（设置里标了「高清」），玩笑音色则整个隐藏。

**断句和语调**：浏览器的语音合成默认把整句用一个音高、一个速度念完，这是「AI 味」的主要来源。现在读例句时会先按标点把句子切成气口（超过 11 词的长从句还会在 and / that / because 这类连接词处再断一次，太短的气口会并回前一句），然后：

断点只认 `. , ; :`（第十三次优化 1）：破折号常常是插在括号、引号里的插入语，拿它当断点容易在不该停的地方断气口，去掉之后更保守，也更不容易断错。

- 音高逐句下沉（1.06 → 0.92），模拟真人说话的语调下倾；
- 最后一个气口放慢到 0.9 倍，模拟句尾拖长；
- 问句的末尾反而升上去；
- 单个单词单独读时降到 0.82 倍速。

所有气口一次性排进播放队列（不靠定时器串联），所以切到后台标签页也不会被拉长。

顶栏的「美音／英音」可以随时切换，设置里可以指定音色、**语速和音量**，并「试听一句」。

## 学习进度与错词

每个词有三种状态：**未学 / 不认识 / 认识**，在答题卡样式的进度条上分别是空白、蓝灰、朱红（原来还有个琥珀色的「模糊」，第二十二次优化取消了）。

记账规则：

- 认识之后又标回「不认识」（包括测验答错）→ 记一次「错过」；第一次就标「不认识」不记，之后改成「认识」是干干净净的认识（第二十三次优化；那天之前记下的「曾错过」一次性清空了，`store.hv` 升到 4）。

于是「认识」分成两种：干干净净的认识，和**曾错过**的认识（词卡上有「曾错过」标签；圆点都是纯红，第二十五次优化去掉了琥珀描边）。
后者是自以为会、却栽过跟头的一批，最值得再看一眼 —— 首页有「曾错过的词」入口。

> 第三次优化里的「反复 ×N」（掌握后又掉下来算特别关注）在第四次优化中**撤销**了，
> 圆点、角标、首页入口和存档字段一并清掉。「曾错过」保留。

标了「不认识」的词都算**待复习**，四个地方可以整理出来重过一遍：首页的「整理错词」、单元页标题旁的「整理错词 · N」、测验结束后的「整理错题」、以及首页的「曾错过的词」。

进入复习后是一个循环队列：标「认识」就从这一轮里划掉，标「不认识」会排到队尾稍后再问，直到清空为止。**还没显示释义时，卡片会先给一句例句当提示**（中文压着不给），设置里可以关掉。

界面上方是这一轮的地形（第五次优化 8）：

- 三个数：**已清 / 待过 / 又错了**；
- 一条进度条，百分比在三个数旁边；
- 右边是答题卡（第二十七次优化，原来是卡片上面一排点子），按抽签后的原始顺序摆开 —— 朱红是已经清掉的，琥珀是又栽了一次的，黑圈是当前这个，空的是还没轮到。

## 测验：错词，或者自己挑的词

测验有两种题源：

- **错词测验**：只考标过「不认识」的词。单元页的「测验」标签是本单元范围，首页的「测验错词」是全站范围。没有错词的单元会直接告诉你去学习模式先过一遍。
- **选中测验**：考你自己勾出来的那一批，不管它现在是什么状态。

答错一律归到「不认识」，原来是「认识」的记一次「错过」。答对不改状态（第三十一次优化）：四选一蒙对也算对，所以结算页列出答对的词，确实会的留着，蒙对的点一下去掉，再一次标成「认识」。不点就什么都不变。

生词本的「测验」考生词本里的全部词，不只考标了「不认识」的。

### 一轮考几个

设置 → 测验里可选 **10 / 20 / 30 / 50 / 全部**，默认 20。

20 是有理由的默认值：一轮两三分钟，正好是提取练习该有的长度，再往后拖准确率就开始掉；
一次考五十个词，后半程基本是在耗着，对记忆没什么帮助。所以第六次优化没有直接把上限提上去。

真正卡人的也不是这个数字，而是**剩下的词考没考到看不见**。所以结算页会写明「题库里还有 N 个这一趟没抽到」，
并给一个「**继续考剩下的 N 个**」——接着考的是这一趟没抽到的词，不会把刚做完的又抽一遍。
45 个错词、每轮 20 题，就是 20 → 20 → 5 三轮扫完，中间随时可以停。
想一次考完就把每轮题数调成「全部」。

### 两种题型混着出

| 题型 | 出的是 | 选项 |
| --- | --- | --- |
| **释义** | 单词 + 音标 + 发音键 | 四个中文释义 |
| **填空** | 例句，生词那处挖成横线 | 四个英文单词 |

有例句的词有一半机会出成填空题。只认得中英对照、放进句子里就不会用，这一关能筛出来。

**句子从三处随机挑**（第十次优化 2）：内置例句、AI 生成的例句、自己写的例句。
自己让 AI 生成一句，在词卡上读过一遍，过几天在测验里挖空再见一次 —— 同一句话的第二次见面，
比再看一遍中文有用。答完后的讲解里会把那句话**填回去完整放出来**，非内置的还标着「AI 例句」或「我写的例句」。

挑句子时会先确认**这句话里真的挖得出空**：挖不出来的句子（比如自己写的时候没把这个词写进去）
不进候选，那道题就出成释义题，不会给你一道没有空的填空题。
挖空只认「这个词本身 + 常见变形」，两头都卡词界 —— 卡片上加粗用的是前缀式匹配（`commend` → `comm…`），
拿它挖空会把句子里的 committee 挖掉，题就废了。

### 干扰项按相似度挑

原来三个干扰项是从全站两千多个词里随机抽的，问 abstruse 而选项里出现「瘟疫」，一眼就能排除。
现在按**同词性 + 释义用字重合 + 拼写开头相同 + 原书同页**打分，从最像的一批里再随机取三个 ——
既不至于风马牛不相及，也不会每次都是同样三个。问 absolve（宣告无罪）时，陪跑的会是「保证，担保」「修订，改进」这类同为 vt. 的词。

**词组额外加强了同词性这一档**（第十三次优化 2）：介词短语的中文释义常常各写各的、字面很难重合（`at the expense of` 和 `at the mercy of` 释义里没几个字一样），原来的打分权重下，这一档基本打不出分，容易被某个单词碰巧沾上一两个字的「释义用字重合」反超，选项就可能变成一个不相关的单词。现在词组配对的同词性分数调高，其他词性不受影响。

### 不会就按「不会」

选项下面还有一个 <kbd>0</kbd>「**不会 · 直接看答案**」（第八次优化 5）。
四选一蒙一个也有 25% 的命中率，蒙对了反而以为自己会了；按「不会」直接翻出正确答案和释义，
记一次「错过」，比蒙一个诚实。

### 什么时候会停下来

| 情况 | 行为 |
| --- | --- |
| 释义题 · 答对 | 停 0.5 秒自动翻篇 |
| 释义题 · 答错 | **停住**，摊开释义 / 词根 / 例句，按「继续」或回车才走 |
| 填空题 · 答对 | **也停住**，把释义过一眼 |
| 填空题 · 答错 | **停住**，同上 |

填空题答对也停，是因为从句子里猜出该填哪个词、和知道这个词什么意思是两件事（第六次优化 2）——
上下文足够强的时候，很可能只是记住了这句话。所以选对之后照样把释义、词根和填好的完整例句摊开，
标一句「选对了 · 顺手把意思过一眼」，回车继续。

答错时那条中文翻译不受「例句的中文翻译先蒙起来」影响 —— 都答错了，正是要看的时候。

### 键盘

<kbd>1</kbd>–<kbd>4</kbd> 直接选选项，答错后 <kbd>回车</kbd>（或 <kbd>空格</kbd> / <kbd>→</kbd>）继续。

### 选中一批词去测验

浏览页、生词本、搜索结果的顶部都有一个「选择」按钮。打开之后每行前面出现方框，三种勾法：

- **点**一行勾一个；
- **按住往下拖**，拖过的整片都跟着变（拖之前那一行是什么状态，整片就设成相反的）；
- **Shift 点**另一行，选中中间一整段；
- 或者直接「全选 / 全不选」。

按 **Esc** 退出选择（第二十九次优化），已勾的词留着。

勾了词，底部会浮出一条横幅：**测验这 N 个 · 拼写 · 逐个过一遍 · 清空**，还有一排色点能给这批词一次标上颜色。

**选择模式下，答题卡上也能圈**（第十一次优化 6）：右边那排小点，点一个、按住拖一段、Shift 点另一个圈中间整段 —— 比在长列表里翻着勾快得多，尤其想连着挑「第 40 到第 60 个」这种。圈完同样用底部那条横幅开测验／拼写／逐个过。

一轮考几个由「设置 → 每轮题数」定，从 10 到 200，或者「全部 · 不设上限」—— 一次把整批词考完，没有上限（第十一次优化 7）。

选中是**全站范围**的：可以在几个单元里各挑几个，再去生词本补两个，凑成一份自己的清单。选中的词存在浏览器里，刷新、关掉再打开都还在，首页也会出现「测验选中的词 · N 个」。

## 拼写检测

单元页第四个标签是「**拼写**」（第十次优化 5）。给中文释义、音标、发音键和一排字母格子，你把词写出来。

认得出 ≠ 写得出：四选一里 abstruse 一眼能认，自己写就未必知道中间是 `-stru-` 还是 `-stro-`。
选择题永远测不出这一层，因为正确答案就摆在眼前。

- **字母格子**一直摆着 —— 几个字母、哪儿断词（词组按空格分段）先给你；
- 「**提示 · 露一个字母**」按一次从头露一个，露过的算「看了提示」，结算页单独计数；
- 「**不会 · 直接看**」跳过蒙的环节；
- 大小写、多余空格、句末的句号都不算错；
- 写错了停下来，**逐字符对齐**标出差在哪 —— 按位置死比的话，少打一个字母后面全算错，看着像整个词都写错了；这里用最长公共子序列对齐，`abbate` 只有多出来的那个 `b` 被标出来。

**拼错不动「认识／不认识」的进度**。那套记的是认不认得，拼写记的是写不写得出，两件事分开记，
才不会把一个只是手生的词判成不会。结算页给三条出路：只写错的这几个、把写错的加进生词本、再来一轮。

## 整理错词界面的几处（第十一次优化）

- **进度条上的点能点着跳词**（2）：那一排小点（第二十七次优化换成了答题卡），点已清掉之外的任意一个，复习队列就转到那个词；已清掉的点现在也能点，见第二十七次优化。以前只能 <kbd>←</kbd> <kbd>→</kbd> 一个个翻，想直接回头看某个刚标错的词得翻半天。
- **「导出这批词」**（3）：复习页标题旁边一个小按钮，点开是一个只读文本框，装着当前这一轮的全部词，Tab 分隔的「单词 / 音标 / 释义」—— 选中复制走，能直接粘回「导入词表」的文本框，也能存到别处。设置 → 词表里还有「复制待复习的词」「复制生词本」，一次导出全站范围的。
- **卡片中文字号可调**（9）：设置 → 卡片里「卡片中文字号」小/中/大/特大，学习、复习、测验、拼写的卡片上中文释义和译文一起缩放。
- **「编辑」「选择」吸顶**（5）：浏览页那排「排序 / 编辑 / 选择」以前只在页面顶端才看得见，往下翻长列表就够不着了。现在它吸在顶栏下面，滚到哪都在。顶栏在窄屏会折行变高，高度是 JS 实测出来的，不会对不上。

每轮几个词跟测验共用「设置 → 每轮题数」。除了单元标签页，勾一批词之后底部横幅上也有「拼写」。

## 搜索

搜索中英文都行（按 `/` 聚焦）。结果按**匹配方式分档**排（第八次优化 1），同一档里按字母序：

| 档 | 什么情况 |
| --- | --- |
| 1 | 整个词一模一样 |
| 2 | 词的开头就是它 —— 输入 `a` 先给 abasement、abate、abbreviate… |
| 3 | 词组里某个词的开头（come to **terms** with）／释义正好由它开头 |
| 4 | 夹在单词中间 |
| 5 | 释义里出现 |
| 6 | 例句里出现（第十四次优化 1） |

以前只判断「含不含这几个字母」，还按原书顺序排：输入 `a` 会先冒出一堆中间带 a 的词，
想找 a 开头的得翻半天。结果最多列 400 条，超出会写明总数。

**第 6 档是例句**（第十四次优化 1）：单词和释义都没搜中，才翻它的例句——内置例句、
自己写的、AI 生成的都翻，命中的话那一行下面会带一小段摘录，写着「为什么是这个词」。
单字符的查询不翻例句（噪音太大，随便一个字母就能命中大半个题库）。

### 查到之后能找到它在哪

结果里每个词后面跟一个**单元标签**（`UNIT 07`、`我加的词`、`导入 · xxx`），
点法有两种（第七次优化 1）：

- 点**这一行**：直接打开这个词的卡片，释义已经翻开，答题卡上也标出它的位置；
- 点**单元标签**：到那个单元的浏览列表里，滚到这个词那一行，高亮闪一下，答题卡跟着标出「第 68 / 68」。

生词本用的是同一套列表，所以那里也有单元标签。

## 浏览排序

浏览页顶部可以换排序：**原书顺序 / 先不认识 / 字母序 / 随机**（第二十八次优化删掉了「先曾错过」「先未学」，存着这两种排序的打开时回到原书顺序）。

- **先不认识** 按 不认识 → 未学 → 认识 排。

顺序在进入单元时定下、离开时重算，所以边学边标不会让列表在脚下乱跳。答题卡和学习模式跟着同一个顺序走。

乱序单元（第二十一次优化）里「原书顺序」那颗叫 **固定乱序**，就是那份写死的乱序。「先不认识」同一档里原来按编号排，编号就是字母顺序，乱序单元里改成按它自己的乱序排，不然一分档又露出字母顺序；原有单元照旧。

## 颜色分组：把一个单元切成几小批

一个单元几百个词，一口气背不完；但「先背前 50 个」这种切法，隔天回来根本不记得切在哪。
所以给词标颜色（第十次优化 3）：**红 橙 黄 绿 蓝 紫**六色，怎么分你说了算 ——
按难度、按词根、按今天要过的那批，都行。深色模式下黄、蓝两色原来偏灰、亮度也和相邻的橙、绿接近，小圆点尺寸下不好分；
调整后黄更偏橙、蓝更偏青，色相上和邻居拉开了距离（第十三次优化 3，只动了深色模式，浅色模式没变）。

标法三种：

- **一次标一批**：浏览页点「选择」勾出一片（列表里或答题卡上都行），底部横幅上点个颜色，整批就标上了；
- **一次标一个**：词卡上音标旁边那颗小圆点，点开是一排颜色，再点一下换或清掉；
- **快捷键**（第十一次优化 4）：学习／复习模式里，<kbd>4</kbd>–<kbd>9</kbd> 给当前这个词标红橙黄绿蓝紫，<kbd>0</kbd> 清掉颜色。翻卡的手不用离开键盘。

标完，浏览页多一行**分组条**：`全部 680 / 红 40 / 黄 25`。点其中一个颜色，
这个单元就只剩这一批 —— **列表、答题卡、学习、测验、拼写全都只走这一批**，
学习模式的「第 N / M」也按这一批算。再点「全部」放开。

**答题卡上也标出颜色**（第十一次优化 1）：每个小点右上角一颗对应颜色的圆点，底下图例列出这个单元用到的颜色 —— 不用点开列表就能看清一个单元被切成了几块、每块多大。

颜色只是分组，跟「认识／不认识」互不影响：列表行左边一道颜色边条，词卡右边一道，进度那道朱红／琥珀的边条还在左边不动。
筛选是临时的，换个单元自然就没了；标好的颜色一直存着。

## 导入自己的词表

首页或设置里的「导入词表」支持 **.numbers**、**.xlsx / .xls / .csv / .tsv**、**.pdf**、**.html** 和纯文本，拖进去或选文件都行。

- **表格**：自动认出哪一列是单词、哪一列是中文释义、哪一列是音标（表头行会被跳过）；
- **PDF**：按文字层的行坐标还原成行再逐行解析。**扫描件或字体不带 Unicode 映射的 PDF 提不出文字**，这时会明确告诉你，建议先转成 Excel / HTML；
- **文档和纯文本**：按行读，`1. abate /əˈbeɪt/ v.减弱`、`abate  əˈbeɪt  减弱`、`abate,减弱` 这几种都能认。

**词组也认**（第五次优化 5）：`prone to 容易…的`、`come to terms with — 接受`、`a piece of cake	小菜一碟` 都能正确切开。
以前是按空格找分界，词组会被砍成第一个单词（`prone to 容易…的` 变成 `prone` + `to 容易…的`）；
现在英文和中文的分界按**第一个汉字**来找，音标先摘出去，末尾的 `v.` `n.` 这类词性标记归到释义那边。
英文部分最多 6 个词 —— 再长就多半是句子而不是词条了。

**同一个词条出现两次而释义不同，会并成一条**（第八次优化 2）。原来按单词去重、第二条直接丢：
一张 166 行的词组表里 `at the expense of` 出现两次（「以…为代价」和「牺牲…」），导进来只剩 165 条，
丢的正是「牺牲」那个意思。现在两条释义用「；」并起来，面板上写明并了几条。

**表格的列判定**也修了：「I1」「A12」这种编号列以前会被当成单词列（第五次优化放宽判定时引入的），
现在编号形状的值不算数；数量打平时看第二个指标 —— 单词列比编号列长，释义列比分类列杂。

**Excel 有好几张表，会拆成好几个单元**（第十二次优化 1）。以前不管一个工作簿里有几张表，
`XLSX.SheetNames.forEach` 读完就直接拼成一个大数组，整本书导进来只有一个单元——
一本 48 个 List 的词汇书，导进来变成一个塞了 4000 多词的巨型单元，原书自己的编排全丢了。
现在每张表各自解析、各自去重，一张表认出的词就是一个单元，单元名是「导入名 · 表名」；
只有一张表的工作簿还是老规矩，不受影响。预览面板也跟着改：表多的时候按单元分组显示，
状态栏会先说清楚「表格有 N 个分页，拆成了 N 个单元，共认出 M 个词条」。

导入前会列出解析结果让你核对，确认后成为新单元（标着「导入」），和内置单元一样可以浏览、学习、测验、搜索。单元页上有「删掉这个单元」。

### Numbers 表格

苹果 Numbers 存的是自家的 IWA 格式：一个 zip，里面每个 `.iwa` 是「4 字节块头 + snappy 原始流」，
解出来是 protobuf。完整还原表格得啃 Apple 没公开的内部结构，但我们只要文字 ——
字符串表（`Index/Tables/DataList*`）里就有，而且大体按行顺序排。

于是自己写了一套（第九次优化 2，不依赖任何外部库，离线可用）：
解 zip（.iwa 是 stored 的，连解压都不用）→ 解 snappy → 扫出所有「变长长度 + 合法 UTF-8」的片段
→ 按「英文词 → 音标 → 中文」的节奏配对。

实测两份真实文稿：142 条和 22 条，单词、音标、释义都对得上。
个别格子会因为 snappy 回指被切碎，**所以导入前一定看一眼预览**；
不满意就在 Numbers 里「文件 → 导出为 → CSV」，或者干脆在表格里全选拷贝、粘到文本框里 —— 那两条路结构完整，更稳。

### 直接粘一段进来

不想存文件就用面板里的文本框，粘进去点「认一认」（第八次优化 8）。单词和意思会自动分开，
`1. abate /əˈbeɪt/ v.减弱`、`prone to 容易…的`、`laconic,简洁的`、`come to terms with — 接受` 这些写法混在一起也认，
认不出的行跳过。带 Tab 的按表格拆。

### 在单元里增删改

自建和导入的单元，浏览页顶上有个「**编辑**」（第八次优化 3）。打开之后：

- 每行右边出现 ✎ 和 ×：改这一条、删掉这个词（连同它的进度、生词本、例句）；
- 旁边多一个「**＋ 添加**」，直接往**这个**单元里加词，不用先去「我加的词」；
- 编辑模式记的是「在哪个单元开着」，所以改完一条它还开着，换到别的单元才关；选择模式一开，编辑模式自动让位。

内置的 37 个单元不给改 —— 那是原书内容，要订正在 `src/ex3/*.tsv` 里改了重新构建。

### 单元改名（第二十九次优化）

单元标题旁边点「改名」，所有单元都能改，目录、词卡、搜索结果里的名字跟着变。原书、托福、雅思这些内置单元留空保存就换回原名；导入和自建的单元名字不能留空。新名字存在 `store.uname`（内置）或 `store.custom` 的 `t`（导入、自建），只改显示，不动词和进度。

### 单元分组（第三十一次优化）

首页默认三组：SAT 词汇（原书 36 个单元和错词本）、托福绿宝书、雅思核心词汇，点组卡片进去是组里的单元，在单元里点返回回到这个组。导入和自建的单元、乱序版单元不进默认分组，摆在首页。

- **新建**：首页的「新建分组」，起名字，勾单元。
- **调整**：组页右上角的「编辑分组」，改名字，勾选或取消单元。勾别的组里的单元就是把它挪过来，取消勾选的回到首页。
- **撤销**：编辑分组里的「撤销这个分组」，单元回到首页，词和进度不动。

一个单元最多在一个组里。分组存在 `store.groups`，和进度一样留在这台电脑的浏览器里。合并单元时分组临时摊开，方便挑。

### 合并单元

分几次导进来的词表，其实常常是同一份东西；单元一多，目录就翻不动了。
首页的「**合并单元**」（第十次优化 1）：点开之后目录变成挑选状态，点两个以上自己的单元，
底部横幅里给合并后的名字，确认前会先告诉你合完多少个词、其中多少条重复。

- 只能合**自己导入或手动加**的单元。原书那 37 页是照着书页排的坐标，动了就和书对不上了 —— 点它们会直接说明原因；
- **同一个词在两份表里都有，就并成一条**，释义用「；」接起来 —— 和导入时同一套规矩；
- 两条的**进度取更需要复习的那个**：一边标着「认识」、一边标着「不认识」，合完是「不认识」；「错过」次数相加；
- 生词本、颜色、例句都跟着留下来；
- 合并后直接跳进合成的那个单元。

### 上千词的大单元

答题卡本来是照着原书一页 68 个词设计的：一个词一个点，铺成四列，正好是侧栏的高度。
导入的词表动辄上千，1200 个点摞起来将近 2000px —— 侧栏比视口高好几倍，`position:sticky` 就失效了；
更糟的是窄屏下答题卡排在卡片前面，进学习模式得往下滚两千多像素才看得见要背的词。

第七次优化 2 的处理：

- 点阵有了**高度上限**（桌面 `100vh - 220px`，窄屏 112px），超出部分自己滚，不再撑开页面；
- 每次翻卡后自动把**当前那个点滚到点阵中间**，不用手找；
- 标题旁边直接写「**第 601 / 1200**」，位置一眼可见；
- 超过 120 词的单元，点阵加一圈边框，看得出来是个可滚动的区域。

实测 1200 词的单元：卡片位置从 2222px 提到 396px，整页高度从 2742px 降到 915px。

高度上限只是让点阵自己滚，1200 个点还是一次性全摆出来——CSS Grid 排版加上
`aspect-ratio` 算高度，这么多节点一次布局、绘制，切单元时仍然看得见一下顿挫。

**第十六次优化 1**：超过 120 词的单元，点阵改成只真的渲染视口内、外加上下各几行
余量的按钮，其余的行拿两个占位块把高度撑住——滚动条该多长还是多长，滚动、
调整窗口大小（窄屏点阵从 4 列变 17 列）时重新算该画哪几行。120 词以内的单元
不受影响，照旧一次摆完。实测一个 1200 词的自建单元：`.rail-b` 从 1200 个
降到约 170 个（滚动中动态换批），拖选、Shift 选中间一段、从搜索结果跳过来
定位这些交互都照原来的手感走——选中范围可以跨出当前渲染的窗口，数据先记下，
滚回去照样看得见选中状态。

## 自己给某个词加例句

词卡上「我的例句」那一栏，除了「生成一句例句」，还有「**＋ 自己加一句**」（第九次优化 1）。两种加法：

**自己写** —— 英文例句 + 中文翻译（可留空）。翻译里对应生词的那一小段用 `**两个星号**` 夹起来，卡片上会标红，和内置例句一个样。

**从一段话里取** —— 把读到的一整段原文粘进来，点「挑句子」：

- 本地挑出**含这个词的句子**，点一句就填进去（不联网、不用 Key）；
- 顺带认出这段话里**还有哪些你词库里的词**，点一下直接跳过去看那张卡；
- 填了 API Key 的话，多一个「翻译这句」，让模型译成中文并自动标出对应片段。

这里的词匹配比卡片上加粗用的那套严：加粗只需在自己写的例句里认出headword，宽松点无所谓；
在别人写的一整段话里找词就不行了 —— `wordPat('commend')` 会切成 `comm[a-z]*`，
把 committee 也算成 commend，concise 撞 conceded、distort 撞 district。
所以扫描用的是「词本身 + 常规屈折变化，且**词尾也卡边界**」。

## 手动添加

首页或设置里的「手动添加」可以一条条敲进去：**单词或词组 / 音标（可留空）/ 中文释义**，回车或点「添加」就存下，
面板不关，接着敲下一个。加进去的词都在「**我加的词**」这个单元里（目录上标着「自建」），和内置单元一样可以浏览、学习、测验、搜索。
面板下方列着已经加过的词，点 × 可以单独删掉；整个单元也可以在单元页上「删掉这个单元」。

## AI 例句（可选）

词卡最下面的「生成一句例句」可以临时给某个词再造一句。设置 → AI 例句里填 DeepSeek API Key（`api.deepseek.com`），模型可选 deepseek-chat（默认）/ deepseek-reasoner。第二十八次优化删掉了 Anthropic 和 Artifact 里直接问 Claude 这两条路，存过的 Anthropic Key 打开时一并清掉。

**例句长度**可调（第八次优化 4）：短 10–15 词 / 中 16–24 词（和内置例句一致，默认）/ 长 25–35 词。

Key 只存在这台设备的 localStorage 里，浏览器直连服务商，不经过任何中间服务器，按量计费走你自己的账号。

提示词会带上这个词的释义和已有例句，要求换一个话题、生词仍是句子主干，并返回英文句 + 带 `**` 标记的中文翻译。
走 `response_format: json_object`（万一某个模型不吃，会自动退回普通模式再来一次，返回里的 ``` 围栏也会被剥掉）。
生成的句子存在本地，可以随时删掉，快捷键 `D`。

## 其他功能

目录（每单元用答题卡样式显示进度）· 浏览 · 学习 · 测验 · 搜索（中英文都可以，按 `/` 聚焦，结果带单元标签）· 生词本 · 导入词表 · 手动添加 · 深浅色切换。

**退回目录停在原来那一屏**（第十次优化 4）。目录、单元浏览列表、生词本这几页是「一长条要翻的东西」，
从里面进去再出来，回到走之前的位置，不用重新往下翻；学习、测验、拼写这些一屏一件事的页面还是从头开始。
已经在目录上再点一次左上角的 SAT 2389，就是「回到最顶上」。

## 自动化测试（第十五次优化 1）

`parseLine` / `parseTable` / `mergeRows`（导入词表用的解析、拼表格、去重合并）和
`lcsMark` / `blankAt`（拼写检测的字符对齐、测验挖空定位）不碰 `document` / `window` /
`localStorage`，只认输入输出——历年也在这几个函数上反复栽过跟头（IPA 正则认串、
编号列当成单词列、`committee` 被 `commend` 挖空……），适合写成回归测试钉住。

这几个函数连同它们要用到的正则常量一起搬进了 `pure.js`：浏览器里还是 `<script>`
在 `app.js` 前面引入、全局函数名不变，`app.js` 里的调用一处没改；`test/pure.test.js`
则直接 `require('../pure.js')` 跑断言——`app.js` 本体不能这样直接 `require`，
它顶层一堆 `document.getElementById(...)`，Node 里没有 `document`，一 require 就炸。

```bash
cd sat2300-web && node --test
```

不需要装任何东西，Node 自带的 `node:test` 跑起来。改了 `pure.js` 或者上面这几个函数的行为，
